Instructor exam focus: “array is a constant pointer”. The intended cue is a fixed array name with mutable elements. Precisely, an array has its own type and often converts to a pointer to its first element. Know both the cue and the exact C++ rule.

01Expressions, types and conversions

  • Zero is false; any nonzero numeric value is true, including a negative value.
  • Postfix supplies the old value; prefix supplies the updated value. Track the expression result and final variable separately.
  • Integer division happens before assignment: double r=5/2; stores 2. Convert an operand first to obtain 2.5: static_cast<double>(5)/2.
  • In-range floating-to-int conversion truncates toward zero. int(-4.8) is -4.
  • sizeof(char)==1 is guaranteed. Other example sizes need an explicit platform assumption.

02Conditions, branches and loops

  • Built-in && and || short-circuit. A skipped operand has no side effects.
  • 3&&4 is true; 3&4 is 0; 3|4 is 7. Truth tests and bit operations are different.
  • A switch chooses an entry label, then statements can fall through. Later cases do not re-test the selector. Case values must be distinct constant integral values after conversion.
  • for: initialize once -> condition -> body -> update -> condition.
  • while tests before entry; do/while tests after the body.
  • break exits the nearest loop/switch. continue skips the rest of the iteration; a for loop still reaches its update.

03Arrays, C strings and records

  • A four-element array has readable indices 0 through 3. One-past is a boundary, not an extra element.
  • int a[4]={7}; gives 7,0,0,0. An ordinary uninitialized local int a[4]; has no such guarantee.
  • A 2D array is an array of row arrays. grid[row][col] selects within a row.
  • char name[]="Ada"; needs four chars, including the null terminator. Its text length is three.
  • A struct groups named fields; padding can make its size larger than the sum of field sizes. C++ structs can have methods and inherit.
  • p->field means (*p).field when p is a valid pointer to the object.

Locate names. Build the program.

04Functions, scope and storage

  • Declaration: what a function is. Definition: its body. A suitable declaration must be visible before a call.
  • Scope controls where a name is usable. Storage duration controls how long its object exists.
  • An ordinary local starts again on each call. A local static initializes once and retains its state across calls in the same run.
  • A local pointer can have automatic storage while its target has dynamic storage. Not every variable written without new is a stack local.

05Declarations, files and the build pipeline

Header declarations -> preprocess/compile -> object files -> link -> executable.

  • A prototype allows checked calls; it does not supply the required implementation.
  • No visible declaration: compilation problem. Required definition missing from linked code: commonly a linker problem.
  • void Weapon::attack(){...} defines a member. A free void attack(){...} is a different function.
  • Include guards prevent repeated inclusion from redefining the class in one translation unit.
  • An object file is compiled code, not an instance of a class.

Follow routes and aliases.

06Pointers and array boundaries

  • int* q=p; copies an address; both pointers can reach the same target. q=&y; changes q alone; *q=9; changes its current target.
  • p+1 advances one element, not one byte. p-q counts elements within the same array or its one-past positions.
  • One-past may be formed but not dereferenced. Null, uninitialized and dangling pointers also cannot be safely dereferenced.
  • *p++ means *(p++); (*p)++ changes the pointed-to value.
  • sizeof(a) on an actual array measures the complete array. In a parameter declared int a[], a is adjusted to a pointer parameter.

08Callbacks and dynamic allocation

  • int (*f)(int,int)=add; is a function pointer. int* f(int,int); declares a function returning an int pointer.
  • f(2,3) invokes the current compatible target. A function-pointer array stores selectable behaviors.
  • new int(5) initializes to 5; new int{} initializes to zero; plain new int does not zero-initialize that scalar.
  • Pair new/delete and new[]/delete[].
  • Deletion ends the target lifetime; pointer aliases are not automatically cleared. Losing the owning address can leak storage.

10Objects, encapsulation and abstraction

  • Class = type; object = instance. Non-static state belongs to each object.
  • Encapsulation controls state changes through permitted operations. A validating setter can preserve an invariant; a getter need not imply a setter.
  • Abstraction exposes the useful interface while hiding irrelevant implementation detail.
  • class defaults to private member/base access; struct defaults to public. Both support C++ class features.
  • Private is class/friend access; protected also supports qualifying derived contexts; public is generally available through an appropriate object/interface.

11Constructors, destructors and lifetime

  • Constructor: class name, no return type. Destructor: ~ClassName(), no return type or ordinary parameters.
  • Declaring an ordinary constructor can suppress the implicit default constructor. A zero-argument construction must have a viable constructor.
  • Base initializes first; members initialize in declaration order; constructor body runs afterward.
  • Required base arguments belong in the initializer list: Studio():Company(5){}.
  • Normal destruction reverses construction. Deleting a derived object through an owning base pointer requires suitable virtual destruction in the ordinary course examples.

Choose behavior. Copy resources.

12Inheritance and virtual dispatch

The static pointer/reference type controls the visible interface. A matching virtual call uses the actual object's final overrider. A base view does not transform or slice the original object; a separate base-value copy can slice.

14Overloading, overriding and Complex arithmetic

  • Overloading chooses a signature; overriding supplies an implementation of an inherited virtual operation.
  • Parameter names and return type alone do not distinguish ordinary overloads.
  • Complex addition combines corresponding real/imaginary components into a result. A non-mutating + leaves inputs unchanged.
  • Prefix: operator++(). Postfix: operator++(int), normally saving and returning the old value.
  • A class defines its own increment meaning. Operator overloading cannot change precedence or invent a new operator symbol.

16pointer chains, const and void*

  • int** pp=&p;: *pp designates p; **pp designates p's int target.
  • int* const p cannot reseat; const int* p cannot write through p; const int* const p restricts both.
  • A pointer-to-const does not freeze a mutable object through every other access path.
  • void* needs a suitable actual typed view before dereference. A cast does not transform the stored object.
  • Pointer + pointer, pointer multiplication/division, and p-=q for two pointers are ill-formed.

17instance and static members

Non-static fields are per object. A static data member is class-shared state. A static member function has no implicit this, so it needs an explicit instance to reach non-static state. A constructor counter counts only the construction paths implemented; it does not automatically count all copies or live objects.

Final pass

Draw addresses separately from values. Separate initialization from assignment. Write the static type and actual type before a virtual call. Check bounds and lifetime before calculating a number.
